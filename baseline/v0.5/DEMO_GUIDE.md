# LingIoT V0.5 快速演示指南

本演示只需要经典 ESP32 DevKit、一个 10 kΩ 电位器和板载 LED。它验证的是“手机配置规则 → ESP32 本地执行”，不依赖云端持续连接。

## 0. 无硬件模拟演示

1. 构建并安装安卓 App（当前仅交付源码）。选择“模拟”，等待能力与初始状态显示。
2. 在 RGB 卡片将 R/G/B 滑块设为 0/80/255，点击“应用”，查看状态色块；舵机与 LED 卡片同理。
3. 在 ADC → LED 本地规则卡片开启“启用”和“高于阈值触发”，保持阈值 1500、回差 100，点击应用。
4. 将模拟输入拖到 1600、1450、1300 mV，逐次观察 LED 预期为开、开、关。开启前台自动读取可查看趋势。
5. 模拟模式不会操作真实硬件；切换连接方式时旧状态和曲线会清空。真实设备操作前核对当前模式。

## 1. 接线

| 电位器引脚 | ESP32 |
|---|---|
| 一侧 | 3V3 |
| 另一侧 | GND |
| 中间滑动端 | GPIO34 |

LED 使用 ESP32 开发板自带 GPIO2 指示灯。不同板子的板载 LED 极性和是否连接 GPIO2 可能不同；若板载 LED 不亮，可接外部 LED，并串联 220–330 Ω 电阻。

**禁止把电位器任何一端接到 5 V。GPIO34 输入不得超过开发板允许的 3.3 V 范围。**

## 2. 烧录固件

1. Arduino IDE 安装 Espressif Arduino-ESP32 3.0.7 和 ArduinoJson 7.4.2。
2. 打开 `firmware/LingIoT/LingIoT.ino`，选择 `ESP32 Dev Module`。
3. 将 `TOKEN` 改成自己的 8–64 位随机口令；修改热点密码，至少 8 位。
4. 保持 `LINGIOT_ENABLE_ANALOG 1`，先不要启用电机。
5. 编译并烧录，串口监视器设为 115200。

## 3. 手机连接

1. 安装 Android Studio 构建出的调试 APK，或在 Android Studio 打开 `android/` 后运行。
2. 选择 BLE，扫描并连接 `LingIoT-Demo`。
3. 输入固件中配置的设备口令，点击“读取设备能力”。
4. 确认出现“读取模拟输入”和“ADC → LED 本地规则”控制卡片。

## 4. 演示本地规则

在手机上设置：

- 阈值：1500 mV
- 回差：100 mV
- 方向：高于阈值时点亮

在“ADC → LED 本地规则”卡片开启“启用”并点击“应用”，或者在 AI 指令框输入：

> 当模拟输入电压高于 1500 毫伏时打开 LED，低于 1400 毫伏后关闭。

核对语音识别文本，再点击“交给 AI 执行”。日志应显示 `set_analog_led_rule` 已执行，并返回 `analog_rule` 配置和 ADC 状态。

慢慢转动电位器：

- ADC 电压达到或超过 1500 mV，LED 点亮。
- 电压回落到 1400 mV 以下，LED 熄灭。
- 在 1400–1500 mV 区间内，LED 保持原状态，避免临界点抖动。

规则由 ESP32 自己执行。手机断开 BLE 后，只要 ESP32 仍然供电，规则仍继续工作。

## 5. 验证规则安全边界

- 手动执行 `set_led` 或 `blink`：自动化规则应被取消。
- 执行“停止 LED / RGB / 电机与规则（舵机保持）”：规则关闭，LED 熄灭。
- 重启 ESP32：规则不应自动恢复，必须重新配置。
- 断开手机但不重启 ESP32：规则继续执行。

## 6. 结果解释

本演示的 ADC 反馈是原始计数和毫伏值，不等于温度、光照或距离。若接入热敏电阻或光敏电阻，需要先建立传感器标定曲线，再增加对应物理量工具；不能让模型直接猜测单位。
